# 赛事影像上传日志分析工具 — 开发计划

## 1. 功能目标与公开接口

- 目标：离线解析五字段日志，输出确定性统计字典。
- 公开接口：
  - `parse_line(line) -> dict | None`：单行解析标准化，非法返回 None。
  - `analyze_logs(lines) -> dict`：接受可迭代/多行字符串，流式统计。
  - `analyze_text(text) -> dict`：兼容旧接口，内部仅调用 `analyze_logs`，禁止独立统计逻辑。

## 2. 输入格式和边界条件

- 五字段：日期 时间 级别 赛事编号 操作，空格分隔。
- 日期 `YYYY-MM-DD` 且为真实日历日；时间 `HH:MM:SS` 范围合法；级别仅 INFO/ERROR；赛事编号 `[A-Za-z0-9_-]+`。
- 操作：`upload_success`；`upload_failed:<原因>`；兼容 `upload_timeout`、`connection_failed`。
- 边界：空输入、空行/纯空白（计总行数并记格式异常）、字段数≠5、非法/不存在日期（记 invalid_dates）、非法时间、非法编号、未知操作、级别操作不匹配、不可解码行（捕获不崩溃）、生成器、多赛事、海量异常（明细上限 1000 + omitted）。

## 3. 核心实现步骤

1. 字段拆分与日期/时间/编号/级别校验，区分日期错误与其他格式错误。
2. 操作解析：成功、失败（提取失败类型）、未知/不匹配判定。
3. `analyze_logs` 统一累加器：计数、`failure_by_type`、`failure_by_event`、`records_by_event`、明细列表与 omitted。
4. 明细追加按 1000 上限，超出递增 omitted。
5. 解码异常在行读取处 try/except，归为格式异常。
6. `analyze_text` 仅委托调用。

## 4. 验收测试和质量门禁

- 覆盖规范第九节全部用例：成功、失败、类型统计、赛事统计、非法日期、非法时间、格式异常、未知操作、空输入、编码异常、生成器、多次运行一致性。
- 断言七条统计约束恒成立（total、valid、failure 两类求和、records 求和）。
- 门禁：全部测试通过、重复运行结果字节级一致、无网络/文件/子进程/eval/exec、仅标准库、Python 3.12。

## 5. 常见失败原因与修复建议

- 日期/时间仅正则不校验真实性 → 增加日历与时域校验。
- 失败类型提取错误（含冒号） → 明确前缀切割规则。
- 未知操作被误归类 → 严格匹配白名单。
- 编码异常中断整体 → 逐行捕获异常。
- `analyze_text` 出现重复统计 → 强制单一逻辑入口。
- 明细超限遗漏统计 → 追加前判断上限并累加 omitted。
