# 赛事影像上传日志分析工具｜开发计划

## 1. 功能目标与公开接口

构建纯计算离线分析器，输出规范性字典。

- `parse_line(line: str) -> dict | None`：单行解析，返回标准化记录或 None。
- `analyze_logs(lines: Iterable[str] | str) -> dict`：主统计入口，兼容生成器与多行字符串。
- `analyze_text(text: str) -> dict`：旧接口，仅转发 `analyze_logs`，不重复写逻辑。

三者共享同一解析与归类函数，保证单一数据通道。

## 2. 输入格式和边界条件

- 每行五个空白分隔字段：日期、时间、级别、赛事编号、操作。
- 日期：`YYYY-MM-DD` 且日历真实；时间：`HH:MM:SS` 范围合法。
- 级别仅 `INFO`/`ERROR`；赛事编号限字母、数字、`_`、`-`。
- 操作归类：`INFO+upload_success` 为成功；`ERROR+upload_failed:原因`、`upload_timeout`、`connection_failed` 为失败并提取原因；级别与操作不匹配、未知操作均判格式异常。
- 空行计入总数并记为格式异常；不可解码行不崩溃，记为格式异常。
- 明细上限 1000 条，超出计入 omitted。

## 3. 核心实现步骤

1. 编写字段切分与五字段校验，区分"日期错误"与"格式错误"两类。
2. 实现操作归类函数，返回 `(kind, failure_type)` 或异常原因。
3. 累加器按规范键初始化；逐行更新计数、明细、omitted。
4. 生成器与字符串输入统一在 `analyze_logs` 归一化处理。
5. `analyze_text` 直接委托主函数。

## 4. 验收测试和质量门禁

- 覆盖第九节全部用例：成功、失败、类型统计、赛事统计、非法日期/时间、格式异常、未知操作、空输入、编码异常、生成器、确定性。
- 校验第五节五条统计等式。
- 门禁：重复运行结果逐字节一致；标准库仅用；无文件读写、网络、子进程、eval/exec。

## 5. 常见失败原因与修复建议

- 空行未计总数：归一化时保留空行，勿过滤。
- 编码异常抛错：入口用 `errors="replace"` 或 try 包裹。
- 两套统计逻辑：删除重复实现，`analyze_text` 仅转发。
- omitted 漏计：先判断明细长度再决定入列或累加。
- 操作误归类：严格匹配白名单，未知一律格式异常。
